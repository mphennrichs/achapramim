# Coleta por scraping nos três marketplaces

Mercado Livre, OLX e Facebook Marketplace precisam ser consultados a cada Scan. A intenção original era usar a API oficial do Mercado Livre para busca (por ele ser o único dos três a expor uma API pública) e scraping como fallback só para OLX e Facebook Marketplace. Na prática, a API do Mercado Livre para terceiros hoje só concede escopo de gestão da própria loja do desenvolvedor da aplicação (itens, vendas, faturamento) — não existe mais um escopo de busca aberta a anúncios de qualquer vendedor no marketplace, mesmo autenticado via OAuth2. Não há alternativa de API oficial nos três marketplaces para este caso de uso.

Por isso, a coleta dos três é feita por scraping de páginas públicas de busca. Essa estratégia é específica por marketplace e vive inteiramente na camada de implementação (adapter/fetcher por Marketplace) — não é um conceito de domínio. O scraping está sujeito a mudanças de layout e bloqueio anti-bot nos três, não só em dois; falhas de um Marketplace não derrubam o Scan inteiro (ver sucesso parcial em CONTEXT.md). Se um dos marketplaces vier a oferecer um caminho oficial de busca de terceiros no futuro, vale reavaliar esta decisão marketplace a marketplace.

## Status da implementação por marketplace

- **OLX**: implementado. Scraping direto por HTTP/browser, sem necessidade de autenticação — a página pública de busca é acessível anonimamente.
- **Mercado Livre**: pendente. Testes de acesso à página pública de busca (tanto via requisição HTTP direta quanto via browser automatizado) resultaram em timeout de conexão consistente a partir do ambiente de desenvolvimento usado até aqui — possivelmente bloqueio de rede a nível de IP/datacenter. Precisa ser revalidado a partir de uma rede diferente (ex: a máquina de deploy real) antes de implementar.
- **Facebook Marketplace**: pendente. Diferente dos outros dois, a página de busca não retorna resultados sem uma sessão autenticada — o HTML carregado sem login é só o formulário de login, mesmo com browser automatizado real. Requer uma conta dedicada (não a pessoal do operador) e captura manual da sessão (cookies) para reuso pelo fetcher, aceitando o risco de a conta ser sinalizada/bloqueada pelo Facebook por automação.
